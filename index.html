How these get built

All three projects are built with Claude Code doing a real share of the implementation work, under a consistent process: plan the approach and get it reviewed before writing code, build it, then verify it for real — run it, click through it, check the database directly — rather than trusting a clean build as proof it works.

A concrete example: adding droppdd's wagers feature surfaced a real bug in the existing data model — the tables tracking weight and workout streaks had no per-user scoping at all, a latent issue invisible until a second feature needed to read that data correctly. Fixing it meant a hand-written SQL migration to safely backfill existing data before making the column required, plus a new session-based auth gate on a page that didn't have one before. That's the kind of thing a build has to actually get reviewed to catch — not something a prompt gets right on the first pass.

There's also a private tool, not linked here, built the same way, to manage and track this job search itself.
